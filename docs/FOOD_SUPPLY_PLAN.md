# 小麦饼供给规划

当前执行以餐桌实时缺口为准：所需饼干 = 向上取整((容量−当前饱腹值)/25)，扣除已有饼干后才制作，默认数量仅补本轮缺口。小麦不足时报告小麦缺口及对应种子产量，仍须扣除在田和种子仓库队列后才是补种数量。餐桌已满或饼干足够时，不制作也不补种。

用户确认种子仓库没有指定数量输入；当前只观察到整批／Shift 半批操作。为避免单块田被多余小麦占用，自动补种暂不启用，不以整批或半批近似需求，不变更其他作物队列。已有队列没有自动清除。

按奇波数量、各只奇波单位时间消耗与工作时长估算每日饱腹需求，后续再接入；不把“每天补满一桌”当成每日消耗。

纯计算模块 `agent/food_supply.py` 已保留，用于后续接入：

1. 目标饼干库存 = 每日饼干需求 × 备粮天数。
2. 需制作饼干 = max(0, 目标库存 − 当前饼干)。
3. 小麦需求 = 需制作饼干 × 4。
4. 扣除背包普通金麦、已在田中预计收获的普通金麦、仓库待种普通金麦种子对应产量。
5. 需补种子 = 向上取整(剩余普通金麦缺口 / 4)，再检查背包种子是否足够。

来源：[普通金麦种子](https://ap-cbt3.csxylic.com/home/seed/1/) 基础产出普通金麦×4；[普通小份波波饼](https://ap-cbt3.csxylic.com/home/product/9102001/) 消耗普通金麦×4。Wiki 的饱腹值字段为 2，与当前游戏卡片显示及实测每份 +25 不同，因此供给模块暂用明确标记的实测值 25，不静默套用 Wiki 冲突数据。

库存或在田数量未识别时返回未知，不当作零，不授权补种。种子返还／进阶、生产效率、不同品质金麦能否替代及按时收获都未计入保底产量。种子仓库会按队列播种且可能自动回收种子，不能仅根据一帧田地图像推算一天产量。

多次补餐记录可以作为后续模型的校验数据；只有同容量、相隔足够长时间、期间未人为添加／取出且餐桌未耗尽时，餐桌差额才可用于估算。现阶段计算模块不接游戏写入，不提供自动播种开关。
