# 家园订单

数据来源为用户确认的 [CBT3 Wiki 家园订单](https://ap-cbt3.csxylic.com/home/order/)，数据版本 0.3.0。

`assets/resource/data/wiki/orders.json` 保存 672 条订单的名称、ID、类型、解锁等级、材料 ID 与数量，以及各自源页面的 SHA256。此处解锁等级是静态条件，不代表当前账号已解锁。订单名称可能重复，必须用实际材料和数量匹配对应变体。

重新导入（缓存中已有页面默认复用；需要刷新时另行审查新版本）：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/import_orders_wiki.py
.\.venv\Scripts\python.exe -X utf8 tools/import_orders_wiki.py --offline
```

`agent/orders.py` 的校验要求名称、物品 ID、需求数量与 Wiki 一致，并且所有材料库存已知且满足保留量。未读取的库存不会当作零；校验不通过不能提交。读取多个订单时应在每次提交后重新读库存，不能沿用提交前的库存连续批准订单。

游戏入口需要在场景里靠近订单看板，出现 `F 订单看板` 后交互。第一阶段从这个交互提示或已经打开的订单页面开始；不包含从任意位置自动行走、家具布局变化后的绕障。

助手中的“家园 · 订单看板”会先处理出货结算和财报，在关闭财报前将明日预告保存至本机 `debug/market_forecast.json`，再切换订单看板。提交前重新识别订单标题、材料数量与提交按钮；提交后同时确认原卡片消失、硬币增加。不刷新订单，不操作提前售出。

当前全部 672 个 Wiki 变体都是单种材料。程序按照实时卡片的名称和需求数量匹配，逐张提交后重新读取其他卡片库存。缺料时调度已适配的六种工作台商品：苗鸡木雕、迷你狼神石俑、浮音风铃、密文环饰、凝质晶球、软绒围巾，以及软木板中间材料。合成链会递归补齐软木板、木炭、尘石砖与风铜锭，分别交给工作台和熔炉；同类空闲设施可以分摊批次，前置产物收获验证后才供下游使用。木炭显式选择游戏内软木配方（3 软木），不直接使用 Wiki 的可选材料默认项。无法制作的原料不足时保留订单并报告。已有未知队列不会取消。详见 [生产流程](WORKBENCH.md)。

两张兽灵之角订单已实测提交，硬币合计增加 10000；之后重复运行没有重复提交，剩余材料不足的订单保留。苗鸡木雕已单独实测制作及收回，尚未遇到缺该成品的真实订单，因此“缺成品订单 → 制作 → 回看板提交”的整链正向证据仍待补。F 交互与首次结算后页面跳转也需要在最终 GUI 队列中继续验证。

用户后续约束：出货箱暂缓；将来只出货本轮自动制作的成品，不处理原有库存。明日行情用于后续备货建议，不将预告当成已验证的次日价格。

[订单看板教程](https://ap-cbt3.csxylic.com/guide/12403/)另有提前出售与午夜出货的说明。订单任务应根据实际页面区分订单提交和商品出售，不能因两者都涉及材料而共用无条件确认节点。

导航可以参考 MaaEnd 的 [MapLocator](https://github.com/MaaEnd/MaaEnd/blob/v2/docs/zh_cn/developers/components/map-locator.md) 与 [MapNavigator](https://github.com/MaaEnd/MaaEnd/blob/v2/docs/zh_cn/developers/components/map-navigator.md) 分层：小地图定位、路径规划、移动反馈与交互。其终末地模型、底图和 BaseNav 数据不能直接用于蓝色星原。当前项目未移植这些模块。
